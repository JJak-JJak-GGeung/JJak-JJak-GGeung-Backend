정산 서버 인계 · 로컬 검산 증빙

B1 서버 연동 검증은 보류. 아래 결과는 서버 실행·실제 승인 저장의 증거가 아닙니다.

단계상태범위
A1/A2로컬 구현·검산 완료실제 서비스 전체 완료와 구분. 회귀 테스트 68개 통과.
B1실제 연동 대기 · 보류DL-A131 실제 OCR 미확인 후보 검산 완료. 실제 확인 후 API/DB 흐름 미검증.
B2로컬 재검산 완료 / 실제 연동 대기DL-A091 자료 확보. 받은 자료 그대로: 주간 명세/청구 100/100kg, 수령·차이 null. A131 확인을 모의한 별도 사례만 96kg·4kg·80,000원.
C1로컬 구현·A06 문장 검산 완료 / 실제 연동 대기제공된 문장을 수동 구조화·모의 확인하여 충돌/중복 메모 검산. 실제 전사·점주 확인·DB 저장 미검증.
C2로컬 구현·A05 원본 수동 전사 검산 완료 / 실제 연동 대기대체 미확인·대체만 확인은 차단. 양측 합의 모의 입력에서만 승인 대상 1,920,000원, 저장 승인액 null. 실제 OCR·확인 이벤트 미확보.
D1/D2로컬 회귀 검산 완료 / 실제 연동 대기승인 저장·잠금·동시 요청·재전송·배포·새 브라우저 조회 미검증.

서버 호출 계약

from app.reconcile.matching import reconcile_receipts
result = reconcile_receipts(**cases["B2_received_sources"]["input"])

from app.reconcile.settlement import reconcile_period, validate_approval
period_result = reconcile_period(**cases["C1_A06_text_simulated_confirmation"]["input"])
# cases는 results.json의 cases 객체. 이 입력은 오프라인 재현용이며 운영에 저장하지 않습니다.
# 실제 서버는 인증·정규화·범위 검증을 거친 DB 자료를 같은 구조로 전달합니다.

reconcile_receipts는 계산 조각이므로 일치해도 승인을 허용하지 않습니다. 전체 근거·유효 청구·합의 판단은 reconcile_period를 사용합니다. OCR 연결부는 B1용이며 수정 청구는 별도의 기간 정산 입력으로 연결해야 합니다.

입력 필수사항

  • 점포·거래처·기간 ID, 고유 납품 행 ID, 문서 ID, 거래 ID, 원문 위치를 서버 DB에서 매핑합니다. offline:·simulated: ID를 운영 ID로 사용하지 않습니다.
  • 확인 수령에는 receipt_id, source_line_id 또는 직접 입력 근거, target_delivery_line_id, received_qty, unit, confirmed_by/at를 전달합니다. 정정은 supersedes_receipt_id와 전체 이력을 함께 전달합니다.
  • 메모는 인증된 확인 텍스트와 거래 ID를 전달합니다. supplier_claim_qty/unit 또는 conflicting은 확인된 구조화 값이어야 하며 계산 함수는 자연어를 판정하지 않습니다.
  • 수정 청구의 replacement와 양측 수량 agreement는 별개입니다. 서버가 실제 확인 이력·근거를 검증한 뒤 전달해야 합니다.
  • 승인 직전 최신 DB 스냅샷과 input_revision으로 validate_approval를 호출하고, 기간 잠금·권한·요청 키 검사와 승인본 저장을 같은 트랜잭션 안에서 처리합니다. 함수는 DB에 저장하지 않습니다.

아직 필요한 자료·검증

  • DL-A091은 제공 파일에 서버 행과 수령 확인 기록이 있습니다. 이 기록은 제공 자료 기준이며 이번에 배포 서버를 재조회하지 않았습니다.
  • DL-A131 실제 서버 행 ID·점주 수령 확인 이벤트가 필요합니다. DL-A091과 같은 기간이라는 서버 검증도 필요합니다.
  • A06 실제 전사 결과·점주 확인 메모 이벤트, A05 실제 OCR 출력·대체 및 양측 합의 이벤트가 필요합니다. 현재는 공개 A06 텍스트와 A05 PNG 수동 전사를 사용했습니다.
  • API 기본 주소·검증용 로그인·기간·행 ID 확보 후 확인 전/후 조회, 같은 요청 재전송, 승인 충돌·동시 요청·새 브라우저 조회를 검증합니다.
